# Research: P1 features — reminders, account logo, editor/viewer roles

Facts verified in the 3.2.4 tree on 2026-09-14 (read-only inventory, `scratchpad/stage4_inventory.md` in the session), decisions D1–D12.

## Reminders

**What exists**: `AccountConfig::SUBMITTER_REMINDERS` saved by `NotificationsSettingsController` (the Pro gate is a no-op off-multitenant), `AccountConfigs::REMINDER_DURATIONS` (16 keys → English strings, no `Duration` helper), `SubmissionEvent` enum value `send_reminder_email` (never created), its icon (`mail_forward`) and locale (`send_reminder_email_to_html`), `AccountConfig::SUBMITTER_INVITATION_REMINDER_EMAIL_KEY` with `DEFAULT_VALUES` (= the invitation texts) and `EMAIL_VARIABLES`, per-template override keys `invitation_reminder_email_subject/body` in `TemplatesPreferencesController::RESETTABLE_PREFERENCE_KEYS`, an unused `recurrent` Sidekiq queue, two empty hooks (`notifications_settings/_reminder_banner` = ccn_not_yet today, `templates_preferences/_submitter_invitation_reminder_email_collapse` 0 bytes). Missing: the mailer method + view, the scheduler, the sender.

**D1 — Scheduler: `sidekiq-cron` 2.4.0, pinned.** Runtime deps `sidekiq >= 6.5` (we run 8.1.6), `fugit`, `cronex`, `globalid`. Schedule `*/15 * * * *` → `CcnSendSubmitterRemindersJob` on the existing `recurrent` queue, loaded by `config/initializers/zz_ccn_reminders.rb` only when `ENV['CCN_REMINDERS_ENABLED'] == 'true'` and `Sidekiq.server?`. Rejected: a self-re-enqueueing job (the chain dies on a crash between run and re-enqueue and needs a boot-time repair), a Coolify scheduled task hitting the API (works only on our infra, invisible in the repo). Constitution III: new gem → pinned + `CCN-CHANGES.md` line; `Gemfile`/`Gemfile.lock` become touched upstream files.

**D2 — Durations**: `Ccn::Reminders::DURATIONS = { 'one_hour' => 1.hour, … 'thirty_days' => 30.days }` (16 entries); a spec asserts `DURATIONS.keys == AccountConfigs::REMINDER_DURATIONS.keys` so an upstream change breaks CI, not production.

**D3 — Due rule and query**: stage `k` = `submitter.submission_events.where(event_type: 'send_reminder_email').count + 1` (k ≤ 3 and the account has `duration_k`); due when `sent_at + duration_k <= now`; late when `now > sent_at + duration_k + 7.days` → skipped for good (protects an old backlog when the feature is switched on, and after an outage). Candidates per account with a reminders config: `Submitter.where(account_id:).where(completed_at: nil, declined_at: nil).where.not(sent_at: nil).where.not(email: [nil, '']).joins(:submission).merge(Submission.active.non_expired).where(sent_at: (now - max_duration - 7.days)..(now - min_duration))`, then per row: template not archived, `preferences['send_email'] != false`, not `Submitters.email_bounced_recently?`, stage due. Oldest `sent_at` first, one stage per signer per run, `CCN_REMINDERS_MAX_PER_RUN` (default 50) deliveries per run. No index on `sent_at`: CCN has hundreds of submitters, not millions; noted as a future additive migration if the sweep ever shows in the slow log.

**D4 — Run lock**: `Sidekiq.redis { |c| c.set('ccn:reminders:lock', run_id, nx: true, ex: 840) }`; the holder deletes it at the end; a second process finds it and exits ("locked"). The event is written right after `deliver_now!` (the invitation job's order), so a crash between the two can at worst repeat one reminder once — never a burst.

**D5 — Mailer without touching `SubmitterMailer`**: `CcnSubmitterReminderMailer < SubmitterMailer` (`app/mailers/`), method `reminder_email(submitter)` mirroring `invitation_email`: `@current_account`, per-submitter/per-template subject/body from `invitation_reminder_email_subject/body`, else `AccountConfigs.find_for_account(account, SUBMITTER_INVITATION_REMINDER_EMAIL_KEY)` + `fetch_config_email_body`, `assign_message_metadata('submitter_reminder', submitter)`, `build_submitter_reply_to`, `maybe_set_custom_domain`, `from_address_for_submitter`, `build_invite_subject`. View `app/views/ccn_submitter_reminder_mailer/reminder_email.html.erb` = the invitation view rendering `submitter_mailer/custom_content` with an explicit path. `Submitters::ValidateSending.call(submitter, mail)` before delivery, as the invitation job does. Skip when `!Accounts.can_send_emails?(account)` (staging: no SMTP → nothing sent, nothing recorded).

**D6 — Observability by API**: `Ccn::Reminders.due(account, now:)` → `[{ submitter_id, submission_id, email, stage, due_at }]`; `Ccn::Reminders.run(account:, now:, dry_run:)` → `{ sent, skipped: { reason => count }, locked, disabled }`. `GET /api/ccn/reminders/due`, `POST /api/ccn/reminders/run` (`dry_run`), `authorize!(:manage, current_account)` (admins only under D9), `Ccn::AdminErrors`, documented in `docs/openapi-ccn.json`; MCP: no new tool (the `account_config` tool already sets the durations; running reminders from a model transcript is not wanted).

**D7 — UI in the hooks**: `_reminder_banner` → the reminder e-mail template form (copy of `personalization_settings/_signature_request_email_form` bound to `SUBMITTER_INVITATION_REMINDER_EMAIL_KEY`, posting to `settings_personalization_path`, the key is already in `ALLOWED_KEYS`); `_submitter_invitation_reminder_email_collapse` → a collapse identical to the invitation one, fields `invitation_reminder_email_subject/body` (already resettable). `_reminder_placeholder` stays dead.

## Account logo

**What exists**: no attachment on `Account`; both blob proxies already treat an attachment **named `logo`** as public (`authorization_check!` returns early) — the upstream Pro name, so e-mail clients can load it without a session; `personalization_settings/show` renders `_logo_form` (ccn_not_yet today); brand asset `shared/_logo` rendered by `submit_form/_docuseal_logo` (← `submit_form/_banner` ← `submit_form/show:20`), `start_form/_docuseal_logo` (← `start_form/_banner`), `shared/_title` (app pages); `layouts/mailer.html.erb` has no header; attribution chain `shared/_attribution` → `_powered_by` (page) and `_mailer_attribution` → `_email_attribution` (mail), rendered by every signer page and the mail layout.

**D8 — Attachment via a concern**: `lib/ccn/account_logo.rb` (`included do has_one_attached :logo; validate :ccn_logo_format end`) included by one line in `app/models/account.rb`. Accepted: `image/png`, `image/jpeg`, `image/webp` by declared type **and** `Marcel::MimeType.for(io)` (magic bytes), ≤ 2 MB; SVG refused (scripts). Controllers: `CcnAccountLogosController` (UI: `create`/`destroy`, multipart, `authorize!(:manage, current_account)`) and `Api::CcnAccountLogoController` (`show`/`update`/`destroy`; `file` as base64, data URI or https URL through `Ccn::DocumentParams`). Rendering: a new partial `shared/_ccn_brand_logo.html.erb` (`account.logo.attached? ? image_tag(logo url) : render 'shared/logo'`) used by the two `_docuseal_logo` partials (2 upstream edits, 3 lines each) — the footer `shared/_attribution` is untouched; e-mails: `layouts/mailer.html.erb` gets one `render 'shared/ccn_mailer_logo'` before `yield` (reads `@current_account`, set by every mailer method; no image when `APP_URL`/`Docuseal.default_url_options[:host]` is blank). Logo URL = the same proxy URL upstream builds for blobs (`blobs_proxy` route `/file/:signed_uuid/*filename`, `ActiveStorage::Current.url_options = Docuseal.default_url_options` is already set by `ApplicationMailer`); resolved during T-logo from `Templates::SerializeForApi`'s document URLs. App pages keep `shared/_title` (DocuSeal mark) — the logo is for signers and e-mails.

## Roles

**What exists**: `User::ROLES = [ADMIN_ROLE = 'admin']`, `role` NOT NULL, default `admin`; `'integration'`/`'superadmin'` used ad hoc; `lib/ability.rb` has zero role branching (every rule account- or user-scoped); `users/_role_select` (CCN hook) lists editor/viewer disabled; `UsersController#role_valid?` and `Ccn::ManageUsers` read `User::ROLES`; `users/index` badge `t(user.role)` and disabled "Add user" for `cannot?(:create, User)`; every settings entry is behind `can?` except the Account link (`_settings_nav:30`, unconditional — the page itself is guarded by `authorize_resource :account`); locale keys `editor`/`viewer` exist in all locales; `TemplateAccess` (per-user template permissions) has schema + preloads but no rules — out of scope.

**D9 — Ability branches (upstream edit, registered)**:
```
case user.role
when 'viewer' then can :read, Template (+ TemplateConditions block), TemplateFolder, Submission, Submitter, User (account) ; own: manage UserConfig, EncryptedUserConfig, AccessToken, McpToken, :mcp ; can :update, User, id: user.id
when 'editor' then viewer's rules + can %i[create update], Template (block) ; can :destroy, Template ; can :manage, TemplateFolder, Submission, Submitter (account)
else (admin, integration, superadmin) → the current rules unchanged
end
```
Effects without controller changes: `/api/ccn/users|webhooks|account_configs|template_folders` → 403 for viewer (no `manage`), editors get folders only; `Api::CcnTemplate*` use `:update`/`:read` on the template → editor yes, viewer read-only; settings nav hides Notifications/Personalization/Users/Webhooks/Esign/SMTP/Storage for both; `ApplicationController` `rescue_from CanCan::AccessDenied` redirects with the message; `Api::ApiBaseController` answers 403 JSON. `User#sidekiq?`, impersonation and the integration user are unchanged.

**D10 — Last-admin guard**: `lib/ccn/last_admin_guard.rb` model validation on `User` (`include` = one line in `app/models/user.rb`, next to the `ROLES` edit): refuses saving when the change would leave the account without an active, non-integration `admin` (role change or `archived_at` set); message `ccn_last_admin_required` en/fr. Surfaces as 422 in `/api/ccn/users` and MCP (`ActiveRecord::RecordInvalid` is already rescued), and in the UI through a one-line `include Ccn::UsersControllerGuard` in `UsersController` (`rescue_from ActiveRecord::RecordInvalid` → `redirect_back … alert:`), because upstream's `destroy` uses `update!`. `_role_select` hook: options enabled.

## Optional bulk list

**D11** — `submissions/new.html.erb:9` shows the "Upload list" tab whenever `@template.variables_schema.blank?` and renders the `_list_form` hook (ccn_not_yet today): no upstream edit needed. Form → `CcnSubmissionsListsController#create` (parse CSV with `csv`, XLSX with `rubyXL` — both in the bundle; ≤ 500 rows; header `email` required; `name`, `phone`, prefillable field columns; `Role: column` prefix when several roles) → `Submissions.create_from_submitters` with `send_email` as chosen → redirect to the template. Implemented only after US1–US3 are green (tasks marked optional).

## Environment, gate, docs

**D12** — `CCN_REMINDERS_ENABLED=true` and `CCN_REMINDERS_MAX_PER_RUN=50` declared in `staging-compose.yml` `environment:` (Coolify passes only declared vars); production compose untouched (flag unset = off). Gate `staging-s4-check.sh`: reminders (set durations by API, create a submission by API, move `sent_at` back with a `rails runner` through `ssh coolify-vm docker exec`, `GET …/due` lists stage 1, `POST …/run` reports the signer skipped for "no e-mail delivery" and writes no event, config restored), logo (upload by API, `/s/:slug` HTML contains the logo `<img>` and still "DocuSeal" + the source link, delete restores the mark), roles (invite an editor and a viewer, read their API tokens into shell variables through the runner — never printed —, run the 200/403 matrix, archive both). `CLAUDE.md` (operations) documents `/api/ccn/reminders/*` and `/api/ccn/account_logo`, the roles and the flags.
